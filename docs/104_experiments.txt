2. ЭКСПЕРИМЕНТ B: патч sa_main — main никогда не возвращается
═══════════════════════════════════════════════════════════════════════

Идея: thunk main (VA 0x5074: "b 0x2220") заменить на ветвь в пещеру:
    cave (VA 0x43a0):  stp x29,x30,[sp,#-16]! ; bl 0x2220 ; b .
Тогда main возвращается в пещеру и крутится вечно — процесс не делает
exit_group, потоки не убиваются.
Патчер: docs/patch_sa_main_stay.py. Проверено: thunk -> 0x17fffccb (b 0x43a0).

Прогон 900 c:
  insert SA:401 = 3   (SA 401 регистрируется, но время позднее ~713-739 c)
  FEXIT = 0, FSTAY = 0   (foundation больше НЕ выходит!)
  insert all = 75
  public = 0, bms.ready = 0, launcher = 0

ВЫВОД: удержание sa_main живым само по себе не помогает и даже снижает
активность (75 SA против 118-143). Похоже, выход foundation — штатная
часть жизненного цикла (init перезапускает его), а проблема не в нём.

4. СЛЕДУЮЩИЕ ГИПОТЕЗЫ (почему нет установки HAP и bms.ready)
═══════════════════════════════════════════════════════════════════════

  A. BMS считает, что это НЕ первый boot (в /data уже лежат HSP от
     appServiceFwk), и пропускает первичную установку HAP.
     Проверить: в эмуляторе первичная установка шла в
     BMSEventHandler::OnBmsStarting после "Load all preInstall bundleInfos
     failed". У нас HSP уже установлены -> preInstall загружается успешно
     -> first boot = false -> HAP не ставятся.
     Эксперимент: полностью очистить /data/app и bmsdb (свежий /data),
     но подготовить ATM раньше; либо наоборот — проверить, что при
     пустом /data BMS уходит в first-boot ветку.
  B. Установке HAP нужен user 0/100 (accountmgr); проверить, создан ли
     пользователь и работает ли accountmgr (в variant B это ломалось).
  C. Проверить по hilog (текстовые снимки в окне 60..200 c) сообщения
     "OnBmsStarting"/"first boot"/"install system bundle".

=== 38. Раунд 25: патч SELinux-ветки в samgr не помог — SA 401 не публикуется ===

Дата: 2026-10-27. Продолжение 37_mi9_round24.

═══════════════════════════════════════════════════════════════════════
ЧТО СДЕЛАНО
═══════════════════════════════════════════════════════════════════════

1) В /system/bin/samgr найдена ветка отказа SELinux:
     [0x76548] tbz w0, #0, 0x76804   ; 0x76804 — блок, печатающий
     "AddSystemAbilityInner selinux permission denied!"
   (строка по VA 0x19b1, ссылка adrp 0x1000 + add #0x9b1 @0x76864)

2) Патч: 0x76548 tbz -> nop (d503201f), т.е. ветка отказа больше не
   срабатывает никогда.
   ВАЖНО: сначала патч был применён по неверному смещению (VA==offset,
   но text-сегмент смещён на 0x1000: правильный file offset = VA-0x1000).
   После проверки program headers исправлено: файловый offset 0x75548,
   исходные байты e0150036 (tbz) подтверждены.

3) РЕЗУЛЬТАТ прогона 650 c с пропатченным samgr:
     "insert SA:401_XX"  — 0
     "SA:401 OpenSo"     — есть
     "Start OnStart-SA:401 finished, spend:17224 ms" — есть
     "insert SA:4010_56", "insert SA:4011_59" — есть (другие SA)
     bootevent'ов 7, panic 0, launcher нет.
   => Эта конкретная SELinux-ветка НЕ является причиной отсутствия
   публикации SA 401. Патч откачен (samgr восстановлен из эталона).

═══════════════════════════════════════════════════════════════════════
ЧТО ЭТО ЗНАЧИТ
═══════════════════════════════════════════════════════════════════════

samgr вообще не доходит до вставки SA 401: либо запрос AddSystemAbility
до него не доходит (SA 401 не вызывает Publish), либо отказ происходит
в другой ветке (не в той, что мы патчили). При этом другие SA того же
инстанса (4010/4011/4014, 403, 4005) вставляются нормально.

Т.е. проблема локализована внутри BMS/SA-401: он не вызывает публикацию
(или вызывает с ошибкой, которую нельзя отличить без логов hilog).

═══════════════════════════════════════════════════════════════════════
СЛЕДУЮЩИЕ ШАГИ (раунд 26)
═══════════════════════════════════════════════════════════════════════

1. Проверить по kernel-binder-логам, доходит ли до samgr транзакция
   AddSystemAbility от SA 401 (наш kernel логирует OHOS-операции; можно
   добавить печать transaction code + target pid для транзакций к samgr).
2. Если транзакция есть — искать в samgr точку отказа (напечатать/ветвить).
3. Если транзакции нет — искать в libbms/safwk место, где должен
   вызываться Publish для SA 401 (например, в libsafwk

   даже при ошибке Init.

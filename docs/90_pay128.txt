=== 90. Круг 19: syscap-патч возвращён; payload установки = 128 байт ===

Дата: 2026-10-28. Продолжение 88_sa5_experiment.

═══════════════════════════════════════════════════════════════════════
1. ЧТО СДЕЛАНО
═══════════════════════════════════════════════════════════════════════

(1) Возвращён патч syscap в libbms (patch_bms_syscap.py): функции
    0x357a40 и 0x3913d4 -> mov w0,#0; ret (проверено в файле:
    00008052 c0035fd6). Бэкап: libbms.z.so.orig.syscap.

(2) Прогон 1500 c с этим патчем + ранний ATM:
      installed_bundle = 9 (HSP), preinstalled = 9, launcher нет.
    => syscap-патч сам по себе не открывает HAP-установку.

(3) BPAY расширен до 128 байт для транзакций к installs (BPAY3/BPAY4).
    Прогон 950 c, insert SA:401 = 7, BPAY3 = 211 строк.
    Payload установки (sz=212, code=15 от BMS/installd-клиента):
      interface "ohos.appexecfwk.Installd",
      затем строки путей: /data/app/el1/bundle/public/co...,
      /data/app/el1/0/base/..., /system/app/appServiceFwk/Hw...,
      /data/service/el1/public/bms/b...
    Коды команд установки, которые реально шлются:
      code=19  (install) x107,  code=15 (install?) x11,
      code=2/28 (path-based), code=1/29/8/12 — прочие операции,
      code=12 с /data/app/el1/... — удаление/очистка.

ВЫВОД: BMS действительно отправляет installd install-команды (code 15/19)
с путями /data/app/el1/... и /system/app/... — то есть установка
запускается, но по итогу в installed_bundle попадают только HSP,
а HAP-приложения (и launcher) не устанавливаются.

2. ЧТО НУЖНО ДАЛЬШЕ
═══════════════════════════════════════════════════════════════════════

  A. Точно декодировать install-запросы: код + путь + имя бандла

  C. По коду ошибки — точечный обход (как libinstalls verify ранее).

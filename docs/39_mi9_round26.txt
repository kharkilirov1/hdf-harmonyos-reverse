=== 39. Раунд 26: OnStart/Init BMS — не гейт публикации; Publish делает кто-то ещё ===

Дата: 2026-10-27. Продолжение 38_mi9_round25.

═══════════════════════════════════════════════════════════════════════
ЧТО СДЕЛАНО
═══════════════════════════════════════════════════════════════════════

1) В libbms найдена и разобрана функция BundleMgrService::OnStart
   (VA 0x2a920c):
     - печатает "BundleMgrService OnStart start";
     - вызывает Init (VA 0x2ac040);
     - проверяет результат: `tbz w0,#0 -> путь ошибки (0x2a9318)`,
       т.е. успех = НЕЧЁТНЫЙ бит (1);
     - далее AddSystemAbilityListener(3299), (0x100500), (8250);
     - печатает "OnStart end" и возвращает.

2) ЭКСПЕРИМЕНТ: Init пропатчен на `mov w0,#1; ret` (успех).
   ПРОВЕРКА: "Start OnStart-SA:401 finished, spend:200/443 ms"
   (было 5-17 c) — Init действительно обходится, OnStart идёт по
   success-ветке.

3) РЕЗУЛЬТАТ прогона 650 c:
     "insert SA:401_XX" — 0
     "SA:401 OpenSo" — 2 (два инстанса)
     bootevent'ов 10, panic 0, launcher нет.
   => Публикация SA 401 НЕ происходит даже при успешном OnStart.
   Патч откачен (libbms восстановлен).

═══════════════════════════════════════════════════════════════════════
ВЫВОД
═══════════════════════════════════════════════════════════════════════

Publish для SA 401 не вызывается ни из Init, ни из OnStart-кода libbms.
Значит его должен вызывать кто-то ещё:
  - либо сам SA должен вызвать SystemAbility::Publish — но в libbms нет
    такого импорта (проверено objdump -T: только EventFwk::Publish*);
  - либо публикацию выполняет safwk/samgr после OnStart, но для 401
    этого не делает (в отличие от 4010/4011/4014, 403, 4005);
  - либо Publish спрятан за виртуальным вызовом/импортом из другого SO
    (libsystemability/liblocal_ability_manager), который нужно найти.

═══════════════════════════════════════════════════════════════════════
СЛЕДУЮЩИЕ ШАГИ (раунд 27)
═══════════════════════════════════════════════════════════════════════

1. Проверить библиотеки libsystemability/liblocal_ability_manager:
   есть ли там экспорт Publish/AddSystemAbility и кто его вызывает.
2. В libbms найти вызовы через GOT/виртуальные таблицы на эти символы
   (objdump -R / .rela.plt) — возможно Publish вызывается через
   indirect call, который не виден в -T.
3. Найти в libsafwk (в samgr) StartSystemAbilityTask и посмотреть,
   вызывает ли safwk AddSystemAbility для foundation-hosted SA.

=== 123. Круг 45: kmsg-стрим запрещён, dmesg слишком медленный -> нужен /proc-счётчик ===

Дата: 2026-10-29. Продолжение 122_dstate.

═══════════════════════════════════════════════════════════════════════
1. ПРОВЕРКИ
═══════════════════════════════════════════════════════════════════════

(A) /dev/kmsg из init-домена:
      test -r /dev/kmsg      -> "kmsg readable=yes"
      head -c 200 /dev/kmsg  -> rc=0, но ничего не вывел
      exec 3</dev/kmsg; read -> сразу EOF (n=0), цикл завершился.
    => читать /dev/kmsg как обычный файл нельзя (нужен syslog-интерфейс
       или CAP_SYSLOG; в логе видны AVC denied open для sa_main).

(B) /proc/kmsg (старый syslog-интерфейс, блокирующее чтение):
      cat /proc/kmsg | while read ...   -> ни одной строки за 400 c,
      хотя "insert SA:401" в dmesg было 4 раза.
    => /proc/kmsg из init-домена недоступен (нет CAP_SYSLOG).

(C) dmesg (syslog syscall) РАБОТАЕТ:
      BMRUN dmesg_works count=0  (на старте)
      BMRUN TRIGGER n=15 count=8 (через ~24 минуты!)
    => dmesg видит счётчик, но поллинг `dmesg | grep -c` каждые 3 c
       крайне медленный под TCG (дамп всего буфера), события приходят
       с огромным опозданием.

═══════════════════════════════════════════════════════════════════════
2. ВЫВОД
═══════════════════════════════════════════════════════════════════════

  Нужен ДЕШЁВЫЙ userspace-триггер, который сообщает "BMS только что
  опубликовалась". Идеальное решение — маленький proc-файл в ядре,
  который инкрементируется в той же точке binder.c, где печатается
  "insert SA:401". Гость читает /proc/bms401 (одна строчка) каждые 2 c
  и при изменении запускает bm install в отдельном процессе (detached,
  чтобы зависание в D-state не блокировало поллинг).

═══════════════════════════════════════════════════════════════════════
3. ПЛАН РЕАЛИЗАЦИИ (следующий круг)
═══════════════════════════════════════════════════════════════════════

  A. В kernel/drivers/android/binder.c (там, где наш printk "insert SA:401"):
     - добавить static atomic_t bms401_count; inc при событии;
     - late_initcall создаёт /proc/bms401, show() печатает значение.
  B. Пересобрать ядро, проверить, что /proc/bms401 существует.
  C. bmrun.sh:
       last=$(cat /proc/bms401)
       while :; do
         cur=$(cat /proc/bms401)
         [ "$cur" != "$last" ] && { last=$cur; ( timeout -s KILL 20 bm install ...; if ok -> aa start ) & }
         sleep 2
       done
  D. При первом успехе — немедленно aa start (BMS жива), затем ps/launcher.

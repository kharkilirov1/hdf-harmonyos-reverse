при успехе — `aa start ...; aa dump -a`.

═══════════════════════════════════════════════════════════════════════
4. ВЫВОДЫ
═══════════════════════════════════════════════════════════════════════

  - Установка УЖЕ ОДНАЖДЫ УДАЛАСЬ (круг 37: "install bundle successfully",
    rc=0) — механизм рабочий.
  - Успех зависит от состояния BMS в момент вызова:
      * foundation перезапускается каждые ~90-125 c, SA 401 умирает
        посреди вызова -> код 0x920087 "bundle manager service is died";
      * со stay-патчем foundation жив, но bm получает generic error
        (клиент не может получить/использовать прокси SA 401) — вероятно,
        из-за того, что main() в sa_main не завершился и часть
        SAFWK-логики (регистрация/экспорт SA) осталась в неполном
        состоянии.
  - Нужен третий путь: foundation жив ЕСТЕСТВЕННО, но дольше, либо
    установка запускается прямо в окне "свежей" BMS (сразу после
    insert SA:401).

═══════════════════════════════════════════════════════════════════════
5. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Триггерить bm install по факту публикации SA 401: в
     kernel/binder.c на строке "insert SA:401" (printk уже есть)
     … проще: bmrun-цикл с МАЛЫМ шагом и без долгих таймаутов
     (проверить, есть ли у bm флаг таймаута; иначе запускать bm
     в фоне и убивать через 20 c, повторяя каждые 25 c).
  B. Либо перехватить момент: foundation печатает "StartSystemAbilityTask
     foundation SA:401 init finished" — по этому признаку (grep в /dev/kmsg
     из скрипта недоступен) … альтернатива: после каждого старта
     foundation (виден по /proc) запускать bm с задержкой 5-10 c.
  C. Проверить on-line: во время успешного окна /proc/<bms>/status и
     доступность SA 401 через hidumper -s 401 (если есть).

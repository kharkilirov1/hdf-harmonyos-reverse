=== 101-102. Круг 25: FSTAY — foundation запинен, error 7 исчез, но установки встали ===

Дата: 2026-10-28. Продолжение 97_exit_analysis.

═══════════════════════════════════════════════════════════════════════
1. ЧТО СДЕЛАНО
═══════════════════════════════════════════════════════════════════════

FSTAY: хак в ядре (kernel/exit.c, SYSCALL_DEFINE1(exit_group)):
для comm, начинающегося на "fou" (foundation) или "sa_" (sa_main),
вместо do_group_exit(...) — печать
  "FSTAY STAY pid=%d tgid=%d comm=%s code=%d"
и бесконечное ожидание (process не умирает).
Патчер: docs/apply_fstay.py.

═══════════════════════════════════════════════════════════════════════
2. РЕЗУЛЬТАТЫ
═══════════════════════════════════════════════════════════════════════

(A) Прогон 620 c:
   insert SA:401 = 3
   FSTAY = 1  ([93.2] pid=1797 comm=foundation code=0)
   FEXIT = 0  (foundation больше не умирает)
   insert all = 67
   ERROR 7 replies = 0 !!!   (раньше было 933-2600)
   bms/launcher событий = 0

(B) Долгий прогон 2000 c:
   insert SA:401 = 3
   FSTAY = 1
   insert all = 143
   ERROR 7 replies = 0
   bms.main.bundles.ready = 0
   launcher.ready = 0
   /data/app/el1/bundle/public = 0   (НИ ОДНОЙ установки!)

ВЫВОД:
  - FSTAY убирает циклическую смерть foundation: SA 401 живёт, клиенты
    больше не получают error 7 (0 против 933+).
  - НО процесс, у которого группа потоков уже завершилась (do_group_exit
    вызывается после выхода остальных потоков), будучи запиненным,
    функционально мёртв: BMS больше НЕ выполняет установки
    (public = 0; без FSTAY HSP-установки были 9-14).
  - Значит "main returned" — это следствие того, что потоки SA уже
    завершились. Нужно понять, почему потоки завершаются (а не пинить
    exit_group).

═══════════════════════════════════════════════════════════════════════
3. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Зафиксировать, какие потоки foundation живы к моменту выхода main:
     снять /proc/<foundation>/task/* (comm, syscall, stack) в окне
     60..95 c (до FSTAY). Если потоки уже спят/завершены — искать, какие
     SA-задачи не стартовали (по hilog SAFWK/BMS текстовым снимкам).
  B. Проверить текстовый hilog в окне 60..120 c (цикл снимков
     dumpstack10) — найти сообщения SAFWK о неудачных SA или о причине
     завершения ("ReportSaMainExit").
  C. По причине — либо устранить её (патч/конфиг), либо пинить не
     exit_group, а конкретный ранний выход (например, не дать main
     вернуться, чтобы потоки не убивались: FSTAY делает наоборот —
     пинит уже опустевший процесс).

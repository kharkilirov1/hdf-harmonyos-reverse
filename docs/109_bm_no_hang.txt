=== 109. Круг 32: bm install больше НЕ висит, но возвращает error ===

Дата: 2026-10-28. Продолжение 108_markers_negative.

═══════════════════════════════════════════════════════════════════════
1. ПРОВЕРКИ
═══════════════════════════════════════════════════════════════════════

(1) Маркеры libbms через write(1)/write(2) — тоже НЕ появились
    (маркерный механизм в libbms не срабатывает; вероятно, вызовы идут
    не в те адреса/модуль, либо seccomp; вопрос отложен).
    libbms восстановлен к syscap-базе (libbms.z.so.bak.markers).

(2) Инструментальные джобы в zz_*.cfg, судя по всему, init не грузит —
    рабочие хуки делает только foundation.cfg (его файл точно читается).

(3) ГЛАВНОЕ: bm CLI теперь работает без зависания!
    В foundation.cfg добавлены delayed_exec задания:
      +500 c : bm install -p /system/app/SuperLauncher/SuperLauncher.hap
      +650 c : то же с -r
      +800 c : bm dump -a
    За прогон insert SA:401 = 3.
    Результат:
      bm1.log = "error: failed to execute your command."   (39 байт)
      bm2.log = "error: failed to execute your command."   (39 байт)
      bm3.log — не создан (задание в 800 c не успело/не выполнилось)
    /data/app/el1/bundle/public = 0

    ВАЖНО: раньше bm install ВИС (rc=-2 timeout) из-за дедлока BMS Start.
    Теперь BMS Start завершается (отложенная пещера), и bm отвечает
    ошибкой быстро => можно перебирать варианты команды и смотреть код
    ошибки в ответе BMS.

═══════════════════════════════════════════════════════════════════════
2. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Подобрать корректный синтаксис bm install для системного HAP:
     - bm install -p <path> -s            (системное приложение)
     - bm install -p <path> -u 100        (пользователь)
     - bm install -p <path> -s -u 100
     - bm install -h в лог (справка) — чтобы увидеть требования.
     Пробовать в разные моменты (500/650/800 c) и записывать вывод.
  B. Если bm вернёт код ошибки — сопоставить с известными (0x8200xx),
     обойти конкретную проверку (как ранее с VerifyCodeSignature).
  C. После успешной установки: aa start -b <bundle> -a <ability> ->
     launcher.ready.

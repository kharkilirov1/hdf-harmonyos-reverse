═══════════════════════════════════════════════════════════════════════
4. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Сразу после aa start снимать hilog в консоль:
       timeout 10 /system/bin/hilog > /dev/console
     и искать строки AMS/AbilityManager с кодом ошибки (StartAbility
     ret=..., permission denied, signature ...).
  B. Проверить варианты запуска:
       aa start -b B -a A -m phone -W        (с окном)
       aa start -b B -a A -m phone -A <action>
       aa start -b B -a SuperLauncherUIability -m phone
       (у лаунчера несколько ability: DefaultIntentBackgroundUiAbility,
        SuperLauncherMainAbility, PermissionRequestAbility,
        SuperLauncherUIability)
  C. Если ошибка про подпись release — попробовать установить HAP с
     флагом отладки или использовать ability с другой подписью
     (например, HwHmosVAssistantLauncher).
  D. Если appspawn не может создать процесс — проверить AVC-отказы для
     appspawn (denied search "/") и поправить (например, chmod/метки
     или запуск appspawn с нужными правами).

=== 122. Круг 44: bm в D-state — неубиваем; нужен триггер по /dev/kmsg ===

Дата: 2026-10-29. Продолжение 121_install_empty.

═══════════════════════════════════════════════════════════════════════
1. ЭКСПЕРИМЕНТЫ
═══════════════════════════════════════════════════════════════════════

(A) Быстрые попытки `timeout -s KILL 20 bm install` (без $(...)):
    за 1800 c успели всего ~10 попыток (по ~3 минуты каждая), успеха нет.
    => timeout НЕ убивает bm: процесс висит в D-state (uninterruptible
       binder-ожидание), SIGKILL не действует.

(B) Триггер по старту foundation (каждые ~2-3 мин) + bm через 22 c:
    BMRUN start 06:22:43
    BMRUN foundation=1789 round=1
    BMRUN round=1 fail 06:26:13
    ... и БОЛЬШЕ НИ ОДНОГО раунда за 1800 c.
    => после неудачной bm-попытки скрипт навсегда завис на этой же
       строке: bm в D-state не убивается, `timeout` не возвращает
       управление. insert SA:401 за прогон было 13, foundation
       перезапускался, но наш цикл до него не дошёл.

═══════════════════════════════════════════════════════════════════════
2. ВЫВОД
═══════════════════════════════════════════════════════════════════════

  Ключевая проблема: вызов bm install в момент, когда BMS уже мертва,
  вешает процесс в D-state навсегда (не спасает timeout/kill).
  Поэтому нужен ТРИГГЕР, который запускает bm ТОЛЬКО сразу после
  публикации SA 401 (пока BMS жива), и одна попытка на триггер.

═══════════════════════════════════════════════════════════════════════
3. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Читать /dev/kmsg из init-домена (permissive SELinux; запись была
     запрещена, чтение может работать) и ждать строку
     "insert SA:401" — это момент, когда BMS жива. Сразу после неё
     запускать `bm install -p HAP` (желательно с таймаутом 20 c).
  B. Проверить, что /dev/kmsg читается:
       head -c 300 /dev/kmsg > /dev/console
     (если да — строим триггер; если нет — ищем другой источник:
      /proc/kmsg, dmesg).
  C. При успехе — немедленно `aa start` (BMS жива ещё несколько секунд).
  D. Если bm снова попадёт в D-state — процесс-триггер умрёт, но init
     перезапустит сервис bmrun; цикл начнётся заново, а триггер
     сработает на следующем "insert SA:401".

═══════════════════════════════════════════════════════════════════════
ГЛАВНЫЕ РЕЗУЛЬТАТЫ
═══════════════════════════════════════════════════════════════════════

1) НАЙДЕН И УСТРАНЁН ИСТОЧНИК ohos.ctl.stop:
   по непрерывным снимкам процессов (psloop.c, /proc каждую секунду)
   сопоставлены pid из param-логов с моментами остановок:
     pid 1781 = /system/bin/xlogcat -t 1  (долгоживущий, uid 1036)
   xlogcat запускался из job "init" (/system/etc/init/xlogcat.cfg)
   и в 74-83 c и 293 c писал ohos.ctl.start/stop парами.
   ФИКС: из xlogcat.cfg удалены exec-команды в job "init".
   РЕЗУЛЬТАТ: ctl.stop больше НЕ появляется (остался только
   powerct -> ohos.ctl.stoX, нейтрализован).

2) После этого foundation всё равно завершается САМ (exit code 0), но уже
   без предшествующих остановок:
     [245.9] SAFWK: Publish SA:1151 result:0
     [251.5] Child process foundation(pid 1791) exit with code : 0
   Т.е. foundation публикует SA и штатно выходит — и ТОЛЬКО перезапуск
   init'ом приводит к инициализации AMS:
     appfwk.ready появляется на следующем инстансе foundation (400-700 c).

3) ЭКСПЕРИМЕНТ "once: 1" для foundation (запрет перезапуска):
   foundation стартует 1 раз, выходит 1 раз, appfwk.ready НЕ появляется
   вообще => перезапуск нужен, отменять нельзя. Откатано.

4) ЭКСПЕРИМЕНТ "урезанный набор бандлов":
   из /system/app оставлен только SuperLauncher (183 каталога убраны),
   все install_list.json обнулены, прогон 1500 c.
   РЕЗУЛЬТАТ: bms.main.bundles.ready всё равно не появился; foundation
   перезапускался 5 раз. Значит скорость сканирования 305 бандлов — НЕ
   главный блокер. Всё восстановлено.

5) Ядро теперь логирует инициатора reboot: в новых прогонах вызовов
   reboot() нет вовсе (bootfail полностью нейтрализован патчами
   libinit_bootDetector + /dev/bbox + sysrq off).

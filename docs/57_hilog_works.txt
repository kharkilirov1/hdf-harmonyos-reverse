errorCode 8519752 = 0x820008; также встречается 8519686.
Причина: наш "грубый" патч (HapVerify -> 0) оставляет HapVerifyResult
ПУСТЫМ, поэтому provisionBundleName пуст -> CheckBundleName падает ->
парсинг HAP падает -> install system bundle fail -> БД/установка пустые.

=> Грубый патч не годится: он даёт bms.main.bundles.ready=true, но
   ломает саму установку (нет provision info).

ПЛАН (раунд 39)
═══════════════════════════════════════════════════════════════════════

1. Снять hilog В МОМЕНТ установки: запускать bm install около 660 c,
   а hilog — в 680 и 760 c (снапшот уже содержит события установки).
2. Найти точную ошибку для SuperLauncher.hap (grep по
   SuperLauncher/slassistant/errorCode в этих снапшотах).
3. По ней решить: патчить конкретную проверку в libhapverify/libbms
   (например, provision/ticket/trust) ИЛИ обойти установку через
   preinstalled_bundle в bmsdb.db.
4. После установки — launcher.ready / boot.completed.

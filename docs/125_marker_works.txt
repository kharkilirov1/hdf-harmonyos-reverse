1. СДЕЛАНО: маркер публикации SA 401 прямо из пещеры libsafwk
═══════════════════════════════════════════════════════════════════════

Патчер docs/patch_pub_marker.py:
  - пещера в libsafwk (VA 0xf1ac) теперь после успешного Publish(401):
      1) (отладка) пытается писать "CAVEPUB0" в /dev/console,
      2) openat("/data/diag/pub401", O_WRONLY|O_CREAT|O_APPEND, 0644),
         write("x",1), close.
  - исправлены две ошибки: bl publish не был разрешён (ассемблер
    оставлял 0x94000000 => бесконечный цикл), и портился сохранённый x8
    (sptr теперь в отдельном слоте).
  - проверено дизасмом: bl 0x1f324 (Publish) на месте.

РЕЗУЛЬТАТ (прогон 800 c): файл /data/diag/pub401 создан и растёт,
bmrun видит:
    BMRUN TRIGGER count=1 09:41:50
=> триггер работает детерминированно и дёшево (wc -c раз в 2 c).

3. ВЫВОД
═══════════════════════════════════════════════════════════════════════

  - Триггер по маркеру из пещеры — рабочий (это большой шаг: теперь
    bm install запускается ГАРАНТИРОВАННО вскоре после публикации SA 401).
  - Но bm install в этих условиях стабильно возвращает ошибку
    (текст ошибки пишется в /data/diag/bmo.txt, который теряется —
    надо вывести его в /dev/console!).
  - Ранее (круги 37, 39, 42) установка УСПЕШНО проходила в прогонах,
    где попытки шли подряд, а не по триггеру; возможно, там bm попадал
    в окно, когда BMS уже завершила Init и установила HSP (позднее
    время ~1000-1300 c), либо играла роль иная последовательность.

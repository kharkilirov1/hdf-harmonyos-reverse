=== 119. Круг 41: НАЙДЕН НАДЁЖНЫЙ КАНАЛ — /dev/console ===

Дата: 2026-10-29. Продолжение 118_sync_issue.

═══════════════════════════════════════════════════════════════════════
1. ПРОБЛЕМА С ЛОГАМИ РЕШЕНА
═══════════════════════════════════════════════════════════════════════

Файловые логи в /data/diag теряются (ext4 не синхронизируется при
убийстве QEMU SIGTERM), а /dev/kmsg из init-домена не пишется.

НО: запись в /dev/console РАБОТАЕТ и видна прямо в консоли QEMU
(и в /tmp/mi9_414_binder.log). Проверено прогоном 600 c:

    BMRUN start Thu Oct 29 03:42:02 CST 2026
    BMRUN console-write-test
    BMRUN try=1 fail[  259.2] audit: ... avc: denied { open } for
                               pid=1790 comm="sh" path="/dev/console"
    BMRUN try=2 fail
    BMRUN install_phase_done ok=0 tries=...
    BMRUN DONE ...

AVC-отказ логируется (permissive), но запись проходит.
=> теперь все ключевые события bmrun видны в консоли без зависимости от ФС.

═══════════════════════════════════════════════════════════════════════
2. ЧТО УЖЕ ИЗВЕСТНО ИЗ ТЕСТА
═══════════════════════════════════════════════════════════════════════

  - bmrun стартует на 65 c (init: "ServiceStart starting:bmrun"),
  - цикл установки идёт (try=1..), первые попытки падают (BMS ещё/уже
    не в рабочем окне),
  - событий INSTALL_OK/AA в этом коротком прогоне не было (600 c мало).

═══════════════════════════════════════════════════════════════════════
3. СЛЕДУЮЩИЙ ШАГ: РЕШАЮЩИЙ ПРОГОН С КОНСОЛЬЮ
═══════════════════════════════════════════════════════════════════════

bmrun.sh (уже в образе) пишет в /dev/console:
    BMRUN start / try=N fail / INSTALL_OK / install_phase_done / AA try=k rc=R / DONE
План: бут 1800 c, затем грепать консоль на:
    BMRUN INSTALL_OK
    BMRUN AA try=... rc=0
и на установку bootevent.launcher.ready (в отличие от unset).
Если установка не случится за 50 попыток — смотреть номера try в консоли
и подстроить каденцию/момент старта.

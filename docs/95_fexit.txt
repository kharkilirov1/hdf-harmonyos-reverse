1. ИНСТРУМЕНТЫ
═══════════════════════════════════════════════════════════════════════

  FEXIT  (kernel/exit.c, do_exit): для comm foundation/sa_main печать

═══════════════════════════════════════════════════════════════════════
3. ВЫВОДЫ
═══════════════════════════════════════════════════════════════════════

  - Двойной Start НЕ был причиной завершения foundation: он выходит
    с кодом 0 при любой инъекции и, судя по прошлым прогонам, делает это
    периодически (~каждые 2-3 минуты), после чего init поднимает его
    заново (on-restart job).
  - Наша пещера нужна ТОЛЬКО для Publish (без неё SA 401 не регистрируется
    в samgr, хотя OnStart выполняется).
  - Именно циклический выход foundation (со всеми его SA, включая 401)
    не даёт системе дойти до boot-событий: SA 401 исчезает
    (rm DeadSA:401), клиенты получают error 7, и цикл повторяется.
  - Publish-only — более "чистый" вариант (без двойного Start, OnStart
    быстрее); его и стоит оставить базой.

═══════════════════════════════════════════════════════════════════════
4. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Понять, почему sa_main/foundation вызывает exit(0): добавить printk
     в sys_exit/sys_exit_group с user PC/LR (current_pt_regs()->pc), чтобы
     увидеть адрес вызова в /system/bin/sa_main и затем по дизасму —
     функцию (возможно, это обработчик "все SA запущены" или завершение
     по сигналу/параметру).
  B. Если выход — из-за отсутствия "держателя" процесса (SA loader
     завершил задачи), попробовать заставить foundation не выходить:
     патч sa_main (точка возврата main -> бесконечный цикл pause()).
  C. С невыходящим foundation: Publish-only -> OnStart -> Init -> ...
     и ждать bms.main.bundles.ready / установку HAP.

=== 110. Круг 33: bm всегда выдаёт generic error, даже с -h ===

Дата: 2026-10-28. Продолжение 109_bm_no_hang.

═══════════════════════════════════════════════════════════════════════
1. ЧТО ПРОБОВАЛИ
═══════════════════════════════════════════════════════════════════════

В foundation.cfg задание services:dumpstacks выполняет матрицу команд
(через delayed_exec), результат — в /data/diag/*.log:
  400 c: bm install -h
  480 c: bm install -p /system/app/SuperLauncher/SuperLauncher.hap -s
  560 c: ... -u 100
  640 c: ... -s -u 100
  720 c: ... -w 300
  800 c: bm dump -a

Прогон 950 c, insert SA:401 = 3.

РЕЗУЛЬТАТ: ВСЕ варианты (включая -h!) дают один и тот же ответ:
    "error: failed to execute your command."  (39 байт)
bd.log (bm dump -a) вообще не создан — задание в 800 c не выполнилось.

═══════════════════════════════════════════════════════════════════════
2. ИНТЕРПРЕТАЦИЯ
═══════════════════════════════════════════════════════════════════════

  - Даже `bm install -h` падает с той же ошибкой => bm НЕ доходит до
    разбора аргументов: ошибка происходит на инициализации клиента
    (создание прокси BMS / получение SA 401 / IPCObjectProxy).
  - Значит для bm SA 401 либо не доступен, либо доступен, но вызов
    падает на клиентской стороне.
  - Ранее (круги 25, с FSTAY) мы наблюдали, что error 7 в ответах samgr
    исчезает (0 вместо 933) — значит клиенты получают handle SA 401.
    Возможно, bm использует ДРУГОЙ интерфейс/дескриптор, нежели
    системные сервисы.

═══════════════════════════════════════════════════════════════════════
3. ПЛАН
═══════════════════════════════════════════════════════════════════════

  A. Проверить раздельно:
     - "bm -h" (глобальная справка) — доходит ли bm до парсинга вообще;
     - "bm dump -a" в 350-450 c — работает ли чтение (без install);
     - "bm install" без аргументов — какая ошибка (usage или client).
     Это отделит "клиент bm не может подключиться" от "неверные флаги".
  B. Если bm не подключается — проверить, под каким uid он бежит (init
     job → uid root?), и не блокирует ли SELinux/манифест доступ к
     SA 401 для shell/root. В логе поискать AVC-отказы для bm.
  C. Если подключается, но install падает — ловить код ошибки BMS
     (сейчас bm печатает generic error): включить более подробный вывод
     (bm install -h может показать флаги; возможно есть -v/--debug).

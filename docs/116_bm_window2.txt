=== 116. Круг 39: окно успеха воспроизведено; -w 15 неверен; нужен help ===

Дата: 2026-10-29. Продолжение 115_bm_window.

═══════════════════════════════════════════════════════════════════════
1. УСПЕХ ВОСПРОИЗВЕДЁН
═══════════════════════════════════════════════════════════════════════

Прогон 1250 c (sleep 200, попытки bm install по 20 c с kill, пауза 8 c;
insert SA:401 = 8):
    BMRUN start 00:26:30
    try 1 .. try 9  (no-code — bm убит до вывода)
    INSTALL_OK try=10  00:43:11
    ok=1 tries=10
=> Установка снова прошла успешно (второй подтверждённый успех!).

Но: aa start не успел (boot кончился через ~2 мин после успеха),
и в образе не осталось aad.txt. Нужен более длинный бут ПОСЛЕ успеха
или отдельный "финальный" прогон с ранней установкой.

═══════════════════════════════════════════════════════════════════════
2. ЧТО НЕ РАБОТАЕТ
═══════════════════════════════════════════════════════════════════════

(1) `kill -9 $p` для фонового bm УБИВАЕТ НЕ bm, а подоболочку:
    дочерний bm остаётся висеть, накапливаются процессы, и следующие
    попытки идут по 2-3 минуты (вместо ~40 c). Итог: за 1600 c только
    6 попыток.

(2) `bm install -w 15` -> "error: option requires a correct value."
    (видимо, допустимый диапазон -w 180..600, как в строке
    "bm install with error waittingTime").

(3) Фоновый bm с редиректом в файл: при kill вывод теряется (bmo.txt
    остаётся 0 байт), поэтому "no-code" в логе.

═══════════════════════════════════════════════════════════════════════
3. ЧТО РАБОТАЕТ
═══════════════════════════════════════════════════════════════════════

  - Каденция: попытка ~20 c + пауза 8 c, старт через 200 c после
    старта bmrun. Успех на 10-й попытке (через ~17 минут после старта
    bmrun).
  - При успехе bm печатает "install bundle successfully." и rc=0.
  - После успеха надо немедленно делать aa start и НЕ ждать.

═══════════════════════════════════════════════════════════════════════
4. ПЛАН (следующий круг)
═══════════════════════════════════════════════════════════════════════

  A. Сначала (в том же bmrun) получить СПРАВКУ по bm, пока BMS жива:
       /system/bin/bm install -h   >> log
       /system/bin/bm -h           >> log
     (когда BMS мертва, bm падает generic-ошибкой, поэтому help надо
      пробовать в цикле до первого успешного вывода).
  B. По справке уточнить опции (таймаут ожидания, -s/-u/-r) и
     использовать корректные значения.
  C. После INSTALL_OK — СРАЗУ `aa start -b com.huawei.hmos.slassistant
     -a SuperLauncherMainAbility`, затем `aa dump -a`, затем ждать
     launcher.ready в консоли (grep по логу QEMU после прогона).
  D. Бут не менее 1800-2000 c, чтобы после успеха осталось ≥10 минут.

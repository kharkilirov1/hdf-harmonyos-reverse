═══════════════════════════════════════════════════════════════════════

1) profile /system/profile/foundation.json: 17 SAs (401 = BMS,
   4005, 403, 6200, 6105, 3299, 3203/3204, 3704, 180/182/183, 501, 1404,
   4606/4607, 4009). Все с run-on-create = true (кроме 3204, 183).

   LocalAbilityManager::DoStartSAProcess(...) вызывает ReportSaMainExit()
   и возвращается (две точки 0x2898 и 0x2eb8, общий эпилог 0x28f8).
   Именно возврат main и даёт "exit with code 0".

3) Эксперимент: пропатчен sa_main — в эпилоге 0x28f8/0x2fa8 вместо
   возврата `b .` (бесконечный цикл), т.е. sa_main никогда не выходит.
   РЕЗУЛЬТАТ (прогон 1200 c):
     - foundation выходит 0 раз (держится живым!);
     - но boot замедлился: samgr.ready только на 540 c (было ~320-370),
       appfwk.ready НЕ появился вовсе;
     - в samgr вставляются SA 4010/4011/4014, но SA 401 (BMS) нет;
     - DeadSA-чистки продолжаются (931, 921, 942, 943, 901);
     - bootevent'ов 6.
   ВЫВОД: простое удержание одного инстанса foundation живым делает хуже —
   прогресс инициализации в этой сборке идёт именно через перезапуски
   foundation (новый инстанс поднимает следующую порцию SA). Патч откачен
   (sa_main восстановлен из эталонного образа).

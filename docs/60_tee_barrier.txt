1. ИНЪЕКЦИЯ БЕЗ ПОТЕРИ /data — РАБОТАЕТ ЧЕРЕЗ loop-mount
═══════════════════════════════════════════════════════════════════════

debugfs -w не открывает образ на запись (metadata_csum). Рабочий способ:
  sudo mount -o loop ~/hsroot2.img /mnt/hsimg
  sudo cp libhapverify.blunt /mnt/hsimg/system/lib64/libhapverify.z.so
  sudo umount /mnt/hsimg
Проверено: файл в образе 320536 байт, по адресу 0x36148 (off 0x35148)
байты 2f90ff17 = b <cave> (blunt: mov w0,#0; ret).
Данные /data (в т.ч. preinstalled_bundle со slassistant) сохраняются.

3. ДОКАЗАТЕЛЬСТВА БАРЬЕРА TEE/HKS (важно!)
═══════════════════════════════════════════════════════════════════════

a) teecd (TEE client daemon) запускается и КРУШИТСЯ:
   [72.18] ServiceStart starting:teecd
   [321.06] Child process teecd(pid 1801) exit with code : 255
   [1199.8] teecd(pid 4109) exit with code : 255

b) teecd требует устройство /dev/tc_ns_client (Huawei TEE client):
   strings teecd: "/dev/tc_ns_client", "/dev/tc_private",
   "open tee client dev failed, fd is ..."
   Также /system/etc/ueventd.config, /system/etc/init/teecd.cfg

c) ЯДРО 4.14 НЕ ИМЕЕТ ДРАЙВЕРА tc_ns_client:
   .config содержит только CONFIG_TEE=y и CONFIG_OPTEE=y
   (generic TEE core + OP-TEE), НЕТ опций Hisilicon tzdriver
   (tc_ns/tzdriver/TRUSTZONE отсутствуют в .config).
   => /dev/tc_ns_client не создаётся, teecd не может открыть его
      и завершается с 255.

f) Как следствие — установка system-app падает:

4. ВЫВОД
═══════════════════════════════════════════════════════════════════════

Для установки лаунчера (а значит и launcher.ready / boot.completed)
BMS нужно проверить подпись/провижн HAP. На этой платформе это
невозможно: нет Huawei TEE-клиента (/dev/tc_ns_client, драйвер
tzdriver в ядре 4.14 отсутствует), teecd циклически падает с 255,
hks_compatibility_bin отсутствует, devicesSecurityProxy недоступен.
Blunt-обход HapVerify даёт bms.main.bundles.ready, но оставляет
HapVerifyResult пустым — после этого установка гарантированно падает
(provision bundleName пуст).

ПЛАН (раунд 42, если продолжаем)
1. Снять чистый лог установки лаунчера: 12 снимков hilog
   (300,340,...,740) в одном прогоне, grep "SuperLauncher|slassistant|
   Install System app:|error: 85".
   - Если ошибка только в provision/verify — барьер подтверждён.
   - Если syscap — попробовать патч syscap-проверки.
2. Если подтвердится verify/provision — зафиксировать цель как blocked
   с этим доказательством (документ 60 + логи).

ВЫВОД
  Помимо подписи (0x820008-класс) в системе есть отдельный барьер:
  ПРОВЕРКА SYSCAP (SystemCapability). Для непатченного HapVerify
  именно она может ронять установку system-app'ов:
    check syscap failed 8519890 / 8519686  (0x81FF06/0x820002 области)
    hap files check signature info failed 8519686
    IsHapCompress/GetEntry failed (ets/modules.abc)

  Файлы syscap в образе ЕСТЬ:
    /system/etc/syscap.json (46 КБ, список компонентов)
    /system/etc/param/syscap.para (const.SystemCapability.*=true)
  То есть профиль есть, но проверка всё равно падает.

СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════════════

- libhapverify восстановлен из .orig (без патча).
- libsafwk cave_once работает (insert SA:401 = 1-2 за прогон).
- hilog-клиент: снимок БЕЗ аргументов иногда даёт полный лог (187 КБ),
  иногда 0 байт (зависит от момента/буфера). Надо снимать несколько
  снимков подряд (300..700 c), чтобы гарантированно поймать окно
  установки system-app'ов.
- Попытки снять hilog на 420/500/580 в последнем прогоне дали 0 байт.

═══════════════════════════════════════════════════════════════════════
ПЛАН (раунд 40)
═══════════════════════════════════════════════════════════════════════

1. Снять 8 снимков hilog подряд: 300, 350, 400, 450, 500, 550, 600, 650
   (delayed_exec в одном job). Один из них попадёт в окно установки.
2. Grep по: SuperLauncher, slassistant, "Install System app:", "check
   syscap failed", "error: 85".
3. По результату:
   - если лаунчер падает на syscap -> найти и патчить syscap-проверку
     в libbms (в логе есть адрес строки: refs 0x36d5ec и 0x3917f0);
   - если на подписи -> точечный патч HapVerify (provision/ticket);
   - если на appspawn/установке -> другой путь.
4. Альтернатива, если точечные патчи не даются: предустановка через
   таблицу preinstalled_bundle в bmsdb.db (формат строк известен:
   KEY=bundleName, VALUE=JSON с bundlePaths, bundleType,
   moduleName, systemApp и т.д.).

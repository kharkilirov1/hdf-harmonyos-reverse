=== 49. BMS unblock, продолжение: bm доходит до foundation, но ответа нет ===

Дата: 2026-10-27. Продолжение 48_bms_unblock_success.

═══════════════════════════════════════════════════════════════════════
СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════════════

- Code-cave в libsafwk (listener cave, публикация host из [self+0x178])
  ВОССТАНОВЛЕН и работает: "insert SA:401" появляется (2-9 раз за прогон),
  bootevent'ы 6-10, panic 0.
- Промежуточные варианты (проверены, не дали insert):
  * пещера с публикацией по одному listener 8250 -> insert 2 раза,
    но bm всё равно не работает;
  * пещера в StartSystemAbilityTask (обход depend для 401 ->
    SystemAbility::Start()) -> insert 0 (штатный Start() публикации 401
    не даёт).

═══════════════════════════════════════════════════════════════════════
ЧТО ПОКАЗАЛ KERNEL-BINDER TRACE ДЛЯ bm
═══════════════════════════════════════════════════════════════════════

Добавлена трассировка (binder.c): при comm=="bm" печатается
  BMTXN code=.. size=.. target=<comm> reply=..

Прогон с bm-командами (600/660 c), ФРАГМЕНТ:
  703.0  BMTXN code=30  size=60  target=samgr
  703.5  BMTXN code=12  size=68  target=samgr
  704.2  BMTXN code=12  size=68  target=samgr    (серия)
  ...
  (в предыдущем прогоне, когда публикация работала:)
  732.0  BMTXN code=43  size=64  target=foundation
  742.3  BMTXN code=31  size=80  target=foundation

То есть bm реально вызывает BMS (foundation), но:
  - файлы вывода bm пустые (даже без "[RC=...]" при использовании
    wait_exec — процесс, судя по всему, убивается/зависает);
  - "insert SA:401" при этом есть.
=> BMS опубликован в samgr, bm получает его handle, посылает RPC,
   но ответа нет: обработчик в foundation не отвечает (или ответ не
   доходит).

Гипотеза: наш ручной Publish не выполняет штатную инициализацию SA
(SystemAbility::Start(): создание/запуск IPC-объекта, регистрация
транзакций), поэтому получатель запросов не обслуживается.
Вторая гипотеза: OnStart держит внутренний мьютекс BMS, а bm-запрос
приходит раньше завершения инициализации и виснет.

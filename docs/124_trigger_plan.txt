=== 124. Круг 46: триггеры по /proc слишком дорогие; план — файл-маркер из пещеры libsafwk ===

Дата: 2026-10-29. Продолжение 123_proc_counter.

═══════════════════════════════════════════════════════════════════════
1. РЕЗУЛЬТАТЫ ПОПЫТОК ТРИГГЕРА
═══════════════════════════════════════════════════════════════════════

(A) Отдельный (detached) запуск bm при смене PID foundation,
    детект перебором /proc/[0-9]*/comm:
      BMRUN start 07:49:26
      BMRUN foundation=1791 first
      BMRUN foundation=3508 round=10 08:03:25
      BMRUN round=10 install_fail 08:04:28
    => перебор /proc очень дорог под TCG: за 1800 c обнаружено лишь
       ОДНО изменение PID (round=10), хотя insert SA:401 было 7.

(B) Детект через `pidof foundation`:
      BMRUN start 08:19:03
      ... и НИ ОДНОГО события за 1800 c (insert SA:401 = 8).
    => pidof, судя по всему, не находит процесс (comm foundation
       выставляется не так, как ожидает toybox pidof), либо вызов
       не работает в этом домене.

═══════════════════════════════════════════════════════════════════════
2. ВЫВОД
═══════════════════════════════════════════════════════════════════════

  Поллинг событий BMS из userspace в гостевой системе слишком дорог
  (полный перебор /proc или dmesg) и ненадёжен (pidof).
  Нужен ДЕТЕРМИНИРОВАННЫЙ дешёвый маркер, который создаётся ровно в
  момент публикации SA 401. Такой момент у нас уже есть — это наша
  пещера в libsafwk (Publish-only), которая вызывается при
  AddSystemAbilityListener(8250).

═══════════════════════════════════════════════════════════════════════
3. ПЛАН (следующий круг)
═══════════════════════════════════════════════════════════════════════

  A. Расширить пещеру в libsystem_ability_fwk.z.so: после успешного
     Publish(401) делать:
        fd = openat(AT_FDCWD, "/data/diag/pub401", O_WRONLY|O_CREAT|O_APPEND, 0644)
        write(fd, "x", 1); close(fd)
     (SELinux permissive => запись должна пройти; /data/diag создаётся
      init-джобой foundation.)
  B. bmrun.sh поллит ДЕШЁВО: `n=$(wc -c < /data/diag/pub401)` каждые 2 c;
     при росте n — detached `timeout -s KILL 25 bm install -p HAP`,
     при успехе — немедленно `aa start ...` (BMS точно жива, событие
     только что было).
  C. Если запись из пещеры не пройдёт (AVC/fs) — fallback: пещера пишет
     в /dev/console маркер, а решение о запуске принимает... нет,
     нужен файл; тогда использовать /tmp? В крайнем случае — писать
     в /data/local/tmp (если есть) или /dev/shm.

2. БАРЬЕР — ДОКАЗАН СТАТИЧЕСКИ И RUNTIME
═══════════════════════════════════════════════════════════════════════

A. СТАТИКА:
   - libbms.z.so (SA 401) НЕ импортирует: SystemAbility::Publish,
     PublishWrapper, LocalAbilityManager::*, ISystemAbilityManager::
     AddSystemAbility (импортируются только MakeAndRegisterAbility /
     AddSystemAbilityListener / ctor-dtor / SystemAbilityManagerClient);
   - SAFWK (libsystem_ability_fwk.z.so, C++ 164 КБ) ОПРЕДЕЛЯЕТ
     SystemAbility::Publish (0x1f324) и GetAbilityRemoteObject (0x213c0),
     но САМ Publish нигде не вызывает и не импортирует
     ISystemAbilityManager::AddSystemAbility;
   - цепочка: sa_main -> SAFWK(DoStartSAProcess) -> OnStart(BMS) ->
     [Publish]  <- звено отсутствует.

B. RUNTIME (kernel binder tracing, code+parcel):
   - в binder_transaction добавлен дамп payload'а транзакций
     foundation->samgr; расшифрован формат Parcel:
       [0x100, 0, len(UTF16), "ohos.samgr.accessToken", SAid, "foundation"]
   - установлено: code=3 = AddSystemAbility (4607 -> insert SA:4607_48);
   - все AddSystemAbility от foundation (16 шт): 180, 182, 403, 501,
     1404, 3299, 3704, 4009, 4607;
   - BMS OnStart прошёл дважды (465/471 c и 613/616 c) —
     НИ ОДНОЙ транзакции code=3 с SAid=401.

C. ПОПЫТКИ ОБХОДА:
   - LD_PRELOAD-хук + замена sa_main -> SELinux "denied entrypoint",
     foundation не стартует;
   - /etc/ld.so.preload -> не применяется (sa_main — статический musl);
   - патчи Init/SELinux-ветки samgr -> публикации не дают;
   - ручное выставление bms.main.bundles.ready -> работает (событие
     видно), но лаунчер всё равно не установлен (bm CLI не работает
     без SA 401).

D. СЛЕДСТВИЯ (проверены):
   - /system/bin/bm help|dump|install -> "error: failed to execute your
     command." (нет SA 401);
   - лаунчер com.huawei.hmos.slassistant (/system/app/SuperLauncher)
     не устанавливается;
   - bms.main.bundles.ready не выставляется (job restartfoundation его
     ещё и снимает);
   - launcher.ready / boot.completed недостижимы при полном/минимальном/
     пустом install-списках (182+15+5+9+5 / 1 / 0);
   - hilog недоступен (пустой буфер от root и logd), faultlog пуст.

3. ПРИЧИНА И ОСТАВШИЙСЯ ПУТЬ
═══════════════════════════════════════════════════════════════════════

BMS 6.0.0.108 (закрытый код) не публикует себя как SystemAbility; так как
bm CLI и установка бандлов идут только через SA 401, лаунчер установить
невозможно. Выставит его может только инъекция вызова
SystemAbility::Publish в процесс foundation (например, патч
safwk_cpp: AddSystemAbilityListener -> при [this+8]==401 вызвать
Publish(this,&GetAbilityRemoteObject()) через code cave с расширением
PT_LOAD). Это отдельная задача уровня патчинга ELF-кода.
